# Contributing

Use an issue-driven workflow. Branches should follow `feature/123-description`, `docs/123-description`, or `fix/123-description`. Use focused imperative commits such as `docs: define initial requirements (#123)`.

Pull requests must explain scope, related requirements, acceptance criteria, testing performed, and documentation changes. Each contributor reviews the other's work where practical and resolves conflicts with the affected contributor.

Definition of Done: the issue is addressed, docs are traceable, relevant checks pass or are reported unavailable, secrets are absent, and the PR is approved before merge.
