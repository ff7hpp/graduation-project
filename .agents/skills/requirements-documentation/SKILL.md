# Requirements documentation

Use stakeholder notes, approved issues, and `docs/requirements/SRS.md`. Separate verified facts, assumptions, proposals, and TBD items; assign stable FR/NFR IDs; link sources and acceptance criteria; then check ambiguity, duplicates, conflicts, testability, and scope. Never fabricate domain details, citations, or outcomes.
